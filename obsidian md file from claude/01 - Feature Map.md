> [!warning] `avg_speed_kmh` and `traffic_congestion_level` timing tension
> The schema doesn't specify whether these are **known in advance** (e.g., from a traffic API for a planned route) or **only knowable after driving**. This matters a lot: if the model is meant to predict energy *before* a trip starts, but training data uses post-hoc average speed, you have a **future-information leakage risk**. Resolve this explicitly before generating data — see [[08 - Leakage]], "snapshot/static-value leakage."

## C — Station dataset features [REAL DATA — actually in your CSVs]

These exist today, but per the schema doc they belong to a **separate charging-recommendation subsystem**, not the trip/energy model. Listed here for completeness and so you don't accidentally merge the two systems.

| Feature | File | Meaning | Unit | Role | Prediction-Time Available? |
|---|---|---|---|---|---|
| `station_name` / `name` | both CSVs | Station identifier | — | Identifier | Yes |
| `latitude`, `longitude` | both CSVs | Location | degrees | Raw | Yes |
| `operator` | `charging_stations.csv` | Network operator | categorical | Raw | Yes |
| `charger_speed_kw` | `ev_station_dataset.csv` | Max charging power | kW | Raw | Yes |
| `available_ports` / `occupied_ports` | `ev_station_dataset.csv` | Live occupancy | int | Raw, real-time | Only if live data feed exists |
| `queue_time_minutes` | `ev_station_dataset.csv` | Estimated wait | min | Likely derived from occupancy | Real-time only |
| `cost_per_kwh` | `ev_station_dataset.csv` | Charging price | currency/kWh | Raw | Yes |
| `traffic_index` | `ev_station_dataset.csv` | Congestion near station | float | Raw/derived | Real-time or forecast |
| `temperature`, `rain_probability` | `ev_station_dataset.csv` | Local weather at station | °C, % | Raw | Forecastable |
| `elevation` | `ev_station_dataset.csv` | Station elevation | m | Raw | Yes |

> [!note] Why this table matters for leakage discipline
> `queue_time_minutes` looks like it might be *derived from* `available_ports`/`occupied_ports` (a ratio or simple function). If a future "station recommendation" model uses `queue_time_minutes` as a feature to predict something that queue time is itself computed from, that's a same-family leakage risk — worth checking once `charger_service.py` is actually implemented.
